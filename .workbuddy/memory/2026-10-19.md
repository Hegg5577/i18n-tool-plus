## 2026-10-19 09:08-09:33 key 详情编辑 + 缺失就地补齐 + JS 语言包写入（commit cea175b）
**用户需求**：① 原版能查看单个 key 下所有翻译，还要一个页面 ② 缺失的检测出来了但不能去补。

**新增 KeyEditorDialog（对齐原版 LocaleTreeItem 交互）**
双击表格行或缺失列表项打开。左侧 key 路径，右侧每语言一行输入框 + 状态标记
（✓已翻译 / 待填写 / 缺失·保存后创建），源语言加粗置顶作为基准。
底部两个批量操作：「用源语言填充空的译文」「清空所有改动」。
只提交真正改动过的字段（对比 open 时的原值），避免无谓写入与撤销记录。

**新增 LocaleWriter 抽象（此前 JS 只能读不能写）**
- `JsonLocaleWriter`：复用 LocaleFileWriter，保序 + 不转义 HTML 字符
- `JsLocaleWriter`：**文本层面精确插入/就地替换，绝不做反序列化再序列化**
  （那会重排引号风格、缩进、注释，diff 完全没法 review）

JS 写入的四个关键点（每一条都是踩出来的）：
1. 匹配**叶子键名**而非完整点号路径 —— JS 是嵌套对象字面量，
   文本里根本不存在 `public.title` 这个字面量，用完整路径 find 永远匹配不到
2. 先定位父对象的括号范围，只在该范围内搜叶子键名，避免改到同名兄弟分支
3. 父对象定位失败则**拒绝写入返回 false** —— 宁可让用户手动加，也不改坏语言包
4. 区分单行/多行格式：单行 `export default { a: { b: 1 } }` 无条件插 `\n` 会把文件截断

**修的 bug**：
1. `JsLocaleWriter.read()` 读构造参数 `text` 而非修改后的 `current`
   → set() 返回 true 但 read() 仍是旧值，像写入没生效
2. 顶层 key（无点号）因 `parts.size < 2` 直接返回 false，无法编辑
3. `JsLocaleParser.removeTrailingCommas` 用 for + i++ 吃掉转义序列两字符，
   第二个字符被再处理一次 → 转义引号被误判为字符串结束、反斜杠丢失，
   导致「写入含双引号的值」无法往返。改 while + continue。

**测试 42 个全绿**（新增 LocaleWriterTest 12 个），含直接对两个真实语言包验证
「只改动目标 key，其余所有值完全一致」。

**踩坑教训（重要）**：
调试时写临时探针测试文件反复被自己的转义搞崩（Kotlin 字符串里要区分
「源码里的反斜杠」和「Kotlin 字符串的反斜杠」）。**正确做法是直接写正式测试并用
字符码 `92.toChar()` / `34.toChar()` 拼装**，不要用多层反斜杠的字面量。
另外定位解析流程 bug 最有效的手段是**分步探针**（把私有方法临时改 internal，
逐步打印中间结果），一次性定位到是第 4 步 removeTrailingCommas 出的问题，
而不是像前面那样反复猜。
