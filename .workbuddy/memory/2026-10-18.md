## 2026-10-18 00:48-00:56 修复「一个国际化都显示不出来」（commit 090172f）

**用户反馈**：读取现在的配置，现在一个国际化都显示不出来。

**根本 bug（自己的实现错误）**：`PathMatcher.resolve()` 的 for 循环遇到 `{locale}` 段就无条件 `return`，
后面的 `{file}` 段永远处理不到。默认模式 `{locale}/{file}` 的实际执行：
`{locale}` → dirs=[en,zh,ja]，isLast=false → 走 else 分支生成 `File(en, "en")` 这种把目录名当文件名的假路径 → `return`
最终 `filter { it.file.isFile }` 把结果全部清空 → 面板空白 + 无行内译文。

**修复**：重写 resolve()，用 `Level(locale, dir)` 逐层下钻，语言跟着路径传递，**只有模式走完才返回**；
区分「独立占位符段」与「占位符+扩展名段」。

**顺带修**：`KeyUsageScanner.scan()` 的 `builtinPatterns` 默认值从 `emptyList()` 改为 `DefaultPatterns.ALL`
—— 默认空会退化成只认裸 `t()` 的兜底正则，`$t()` / `i18n.t()` 全部识别不到。

**首次建立测试基线（src/test，16 个测试全绿）**：
- `PathMatcherTest` 12 个：4 种路径模式、连字符语言名（zh-CN）、缺文件不产脏数据、嵌套/平铺 key、缺失多余判定、源语言缺失时退化策略
- `RealProjectScanTest` 4 个：**直接读真实项目** `E:/CompanyItem/ai-station-web` 验证
- `build.gradle.kts` 补 `testImplementation` gson + junit（compileOnly 在测试运行期不可用，这坑踩过）

**真实项目调研结论（重要）**：
扫了 `E:/CompanyItem/` 下 8 个前端项目，语言包有两套结构：
1. `ai-station-web` / `software-store-next-web`：`src/i18n/locales/{locale}/index.json`（JSON，1135 key，13 语言）← **默认配置即可**
2. `up3d-software-operation-web` / `up3d-edu-professional-web` / `design-center-web` / `edu-admin-web` / `up3d-education-web` / `dental-station-web`：`src/lang/{locale}.js`（**JS 文件，不是 JSON**）

`ai-station-web` 实际用**裸 `t('key')`** 写法（如 `t('common.returnOrder')`），
装的是 i18next + react-i18next + react-intl，`src/i18n/dictionaries.js` 里 import 各语言 json。
注意：grep 时必须包含 `.jsx`，只搜 `.ts/.tsx` 会误判为「未接入」。

**教训**：纯逻辑层（PathMatcher/LocaleRepository）从第一天就该配测试。
这次「一个都显示不出来」如果当时有测试，构造 `{locale}/{file}` 的样例目录就能立刻暴露，
不用等到用户实际使用才发现。
