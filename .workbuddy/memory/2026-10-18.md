## 2026-10-18 00:48-00:56 修复「一个国际化都显示不出来」（commit 090172f）

**用户反馈**：读取现在的配置，现在一个国际化都显示不出来。

**根本 bug（自己的实现错误）**：`PathMatcher.resolve()` 的 for 循环遇到 `{locale}` 段就无条件 `return`，
后面的 `{file}` 段永远处理不到。默认模式 `{locale}/{file}` 的实际执行：
`{locale}` → dirs=[en,zh,ja]，isLast=false → 走 else 分支生成 `File(en, "en")` 这种把目录名当文件名的假路径 → `return`

**修复**：重写 resolve()，用 `Level(locale, dir)` 逐层下钻，语言跟着路径传递，**只有模式走完才返回**；

## 2026-10-18 10:19-10:32 JS 语言包 + 缺失检测 + Key 列修复（commit 24304cd）
**用户反馈三件事**：① key 那一列为什么是缺失的 ② 需要支持 js 语言包 ③ 缺失的没找出来。

**① Key 列整列显示「缺失」（极具误导性的 bug）**
根因：JTable 按「列的声明类型」查渲染器，Swing 里 `Object` 是所有类型的父类，
所以 `setDefaultRenderer(Any::class.java, renderer)` 注册一次后**所有列都走它**，
包括 Key 列（值是 String）。而 `TranslationCellRenderer` 只认 `CellData`，
`as? CellData` 返回 null 就走 `<缺失>` 分支 —— 于是 Key 列整列显示「缺失」。
**验证方式**：写了个独立 Java 程序（`java.exe --source 11 T.java`）证明
`getCellRenderer(0,0)` 与 `(0,1)` 返回同一个 Object 渲染器。
修复：渲染器显式 `if (value !is CellData) return JLabel(key)`。

**② JS 语言包支持（新增 JsLocaleParser）**
vue-i18n 项目语言包是 `src/lang/{locale}.js`，形如 `export default { public: { title: "x" } }`。
规整流程：状态机剥注释（必须保留字符串里的 `//`，URL 里就有）→ 剥离 export/default/module.exports →
裸键名补引号 → **单引号与反引号统一为双引号** → 去尾随逗号。
**踩坑**：一开始只做了「补键名引号」，结果 `ok: '确定'` 照样解析失败返回 {}；
JSON 只认双引号，必须同时归一化字符串引号。
另外 Kotlin 块注释里写 `/* 头部注释 *\/` 这种字面量会提前闭合注释，编译报 Unclosed comment。

**PathMatcher 两个推断错误**：
1. `localeFromFileName` 只 `removeSuffix(".json")` → 11 个 `.js` 文件全被标成语言 `js`（实测输出 11 个 `js`）
2. `index.js` 是 vue-i18n 聚合入口，被当成语言 `index` → 新增 AGGREGATE_NAMES 排除
3. 扩展名匹配用 `endsWith("js")` 会误匹配 `xx.mjs` → 改用 `file.extension.equals(...)`

**③ 缺失检测（新增 UsageScanner + 侧边栏「缺失检测」标签页）**
关键洞察：「翻译对照」只看语言包之间的差异，发现不了「代码写了 `t('a.b')` 但语言包没有 `a.b`」——
而后者才是真正导致界面显示原始 key 的问题。扫描源码 key 与语言包比对，产出缺失/多余两份清单。
设置新增「源码目录」配置项（默认 `src`）。

缺失 2 个：`Common.cancel`（疑似大小写写错，语言包里是 `common.cancel`）、`nest.confirmAddNum`（真缺）
多余 1015 个（多为 `account.text1` 这类历史遗留）
