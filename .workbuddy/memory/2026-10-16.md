- 源项目能力清单中尚未覆盖的：hover 预览、硬编码字符串提取、过期翻译检测（源文本变更比对）、namespace 管理、多翻译引擎（DeepL/Baidu/OpenAI）、翻译审阅协作、30+ 框架适配、YAML 自定义框架、in-place 全量替换显示模式。

## 17:25-17:50 阶段1 完成（UI 重做 + 框架抽象层）
**范围确认**：用户选定只做 4 个框架 —— i18next、vue-i18n、react-i18next、i18n-js，覆盖 js/jsx/ts/tsx/vue/html。
**源项目核实**：i18n-ally-next 实际是 29 个框架（非"30+"），src/frameworks/ 共 33 个 ts文件（扣base.ts 与 index.ts），约 1900 行，平均每个 65 行 —— 框架本质是声明式配置（id + key正则 + 语言列表 + 依赖检测规则），移植成本远低于预估。

**本阶段产出**（commit e848005，+1129/-131）：

**关键踩坑（重要，后续务必沿用）**：
- 本平台（WebStorm 2026.1.4 / 平台 262）上 `SimpleTextAttributes.regular()/grayed()`、`UIUtil.getSmallFont()`、`JBUI.CurrentTheme.Table.separatorColor()`、`JBUI.Borders.customLineBottom(color, 1)`（只接受 1 个参数）、`JBTable.defaultRendererFor()` **均不存在**。
- 解法：UI 层只用最基础 Swing + `JBColor` + `UIUtil.getLabelFont()` + `JBUI.Borders.empty()/customLineRight(color)`；表格渲染器自行实现 `TableCellRenderer` 接口而非继承平台的 ColoredListCellRenderer。

- Kotlin 字符串里写正则含 `$`（如 Vue 的 `$t`）必须转义为 `\$`，否则被当模板变量导致 UNRESOLVED_REFERENCE。
- git .gitignore 原先漏了 `.intellijPlatform/` 和 `.kotlin/`，导致沙盒缓存被提交；已修正，基线 23 个文件。

## 17:55 用户实测反馈 + 两个严重 bug 修复（commit 3f766cf）
用户装上插件截图反馈：列头乱码豆腐块、大量 ⚠ 已过期标记。
**Bug 1（严重，逻辑根本错误）**：`looksStale` 判定 = 「译文≠原文 且 占位符集合一致」。
机器翻译的译文本来就与原文不同，且两边无占位符时空集相等 → **所有已翻译条目 100% 被误判为过期**。
修复：整个 STALE 状态与判定逻辑已删除，只保留三态（已翻译/待填写/缺失）。
**教训（重要）**：过期检测必须有源文本历史快照才能做，凭「译文≠原文」推断必然误报。注释里写"避免误报"却做出"保证误报"，说明写推断逻辑前必须先想清楚误判面。
**Bug 2**：国旗 emoji 在 Windows 渲染成豆腐块□（系统缺彩色 emoji 字体）。改为只用 JDK Locale 输出「日本語 (ja)」文字标签。
**顺带修正**：基准语言原逻辑在配置源语言不存在时取 `all.first()`（字母序首个，可能是 `ar` 阿拉伯语）→ 整表以阿拉伯语为原文显示。改为优先取 key 数量最多的语言；displayLocales 提到列序最前。
**当前状态**：UI 能用但仍有明显待补 —— 表格无排序/筛选/搜索、只有三个基础能力、未接设置面板、无 hover 与提取。
**待用户确认**：实际项目的语言包路径与目录结构（`src/i18n/locales/{locale}/index.json` 是否正确、是否存在 en 源语言目录），以及 `t()` 调用的实际写法。

## 18:00-18:10 匹配逻辑配置化（commit d30ec41）—— 用户指出核心设计缺陷
**用户反馈**："现在是以什么匹配的？不是key吗？语言包路径、源语言、t() 写法都应该是可配置的，你看 i18n-ally-next 的配置。"
**根因**：之前把三件事全硬编码了 —— 路径写死 `src/i18n/locales/{locale}/index.json`、源语言写死 `en`、`t()` 正则写死在 4 个框架类里，导致不同项目必须改代码才能用。
**原版机制确认**（src/frameworks/custom.ts + docs/config/custom-framework.md）：
- `.vscode/i18n-ally-next-custom-framework.yml` 单文件配全部，字段含 languageIds / usageMatchRegex（`{key}` 占位符）/ refactorTemplates / namespace / namespaceDelimiter / scopeRangeRegex / monopoly，支持热重载
- `pathMatcher` 用 `{locale}` `{namespace}` 占位符描述任意目录布局
- **本次实现（JetBrains 版，对应 .idea/i18n-helper.xml）**：
  - 新增 `PathMatcher`：支持 {locale}/{namespace}/{file} 占位符，覆盖 4 种常见布局
  - 新增 `KeyStyle`：nested/flat/auto
  - `KeyUsageScanner` 支持用户自定义正则，配了就只用它（不混内置规则）
  - 新增 `I18nContext` 统一读配置，UI/扫描/批量翻译/行内提示共用；TranslationIndex 缓存指纹含全部配置，改设置自动重解析
  - **删除了 framework/ 整层** —— 正则已内置到 DefaultPatterns，框架抽象层成了冗余第二套逻辑
  - 新增设置面板 I18nConfigurable（Settings → Tools → i18n Helper）
  - 表格加搜索框 + 状态过滤 + 匹配计数 + 配置警告
**新增踩坑**：`BoundConfigurable` 在本平台是 Kotlin DSL 版本（返回 `DialogPanel`），要用 `Configurable` + 显式 reset/apply。
**仍未做**：硬编码提取（CodeLens）、hover 多语言预览、多翻译引擎、key 重命名、i18n-ally 的 YAML 自定义文件（目前走 IDE 设置面板，非项目内 yml）。
